5. token 분할·문서 버전·중복 적재·인덱스 활성 전환·출처 ID 검증에 빠진 것이 있는가?

7. graph와 trace를 통해 원문·개인정보·예외·metadata가 누출될 수 있는가?
8. 검사 순서·세션 위험·예산 예약·용량·timeout·취소·native 추론 정리가 보장되는가?
9. Llama/E5의 Windows 실행·모델 동시 메모리·동기/비동기 경계에 무리한 가정이 있는가?

## 2. Claude의 회신 뒤 처리

Codex가 각 지적을 아래 형식으로 정리해 최종안에 반영한다.

| 지적 ID | 판단 | 근거 | 변경할 설계 | 확인할 시험 |
|---|---|---|---|---|
| Claude 회신 후 작성 | 수용 / 보류 / 반박 | 현재 미작성 | 현재 미작성 | 현재 미작성 |

P0/P1은 해소하거나 대표님이 이유를 확인한 보류로 정리한다. 미해결 항목을 완료로 바꾸지 않는다.
그 뒤 최종 개발안 v1을 확정하고 단계별로 구현한다. Claude가 검수했다는 이유만으로 코드가 검증됐다고 하지 않는다.
