필수 목표:
- LangChain: 메시지/프롬프트/LCEL/구조화 출력과 retriever.
- LangGraph: retrieve → 근거 분기 → generate 또는 ask_for_materials의 작은 고정 graph.
- LangSmith: 개인정보 전송을 제한한 tracing과 합성 dataset 평가.
- RAG + 임베딩 + 벡터 RAG + memvid를 모두 실제 구현 대상으로 포함.
- 생성은 Llama 계열, 임베딩은 로컬 multilingual-e5-large-instruct 우선 검토.
- Qwen은 대표님 방침에 따라 기본 실행에서 제외.
- 기존 API 3개 유지, 최종 앱은 최대 11개. 최초 새 기능은 guidance에만 연결.
- 합성 안내문 10개와 질문 20개로 작게 시작. 멀티에이전트/반복 재검색/외부 벡터 DB는 제외.
- 벡터·코사인 유사도는 최소 개념 공부에 한정. 별도 리서치 시스템·개인 검색식·질의 요약기·맞춤 랭킹 설계는 추가하지 않음.

4. memvid SDK가 외부 문서 벡터와 query 벡터를 실제 지원하는지 먼저 시험하도록 설계됐는가?
5. token 분할·문서 버전·중복 적재·인덱스 활성 전환·출처 ID 검증에 빠진 것이 있는가?
6. top-k 결과만으로 근거 있다고 판단하거나 임의 cosine 임계값을 쓰는가?
7. graph와 trace를 통해 원문·개인정보·예외·metadata가 누출될 수 있는가?
8. 검사 순서·세션 위험·예산 예약·용량·timeout·취소·native 추론 정리가 보장되는가?
9. Llama/E5의 Windows 실행·모델 동시 메모리·동기/비동기 경계에 무리한 가정이 있는가?
